# AGRV2K main Flash

The `feat-agrv2k-support` branch provides an opt-in, isolated `agrv2k`
target and native NOR Flash driver for VF407 / AGRV2KL100. Enable it with
`--enable-agrv2k`. The generic `src/target/riscv/` implementation is unchanged.

Writes execute a stackless RV32I loader from a backed-up SRAM working area.
The host preloads blocks using batched SBA writes; the hart uses the
controller's continuous FastProgram mode and closes each block before
checking completion. Source transfers do not compete with an executing
writer for SRAM access. The loader source, linker script and generated bytes are
under `contrib/loaders/flash/agrv2k/`; rebuilding those bytes requires a
RISC-V ELF toolchain, but building OpenOCD itself does not.

The isolated target also implements SRAM algorithm execution and uses the
upstream RV32 CRC loader for `verify_image`. Algorithm completion, unexpected
exit and timeout restore GPRs, PC, writable DCSR state and interrupt state.
Working areas are restored by OpenOCD's allocator. A failed write is reported
without replaying the partially issued transfer or switching to a slower
writer. If a hart cannot be halted, its SRAM is left intact; reset and
reconnect before retrying.

The default scratch region is `0x20018000..0x20020000`, away from the low
SRAM occupied by VF407 Ethernet DMA descriptors. Halting the hart does not
stop DMA. An application must keep this scratch region free of active DMA;
override `AGRV2K_WORK_AREA` and `AGRV2K_WORK_AREA_SIZE` before loading the
profile if it uses a different DMA layout. Intermediate blocks end on page
boundaries; the controller commits a final partial page when FastProgram closes.

## Programming

Use the CMSIS-DAP profile for the AGM probe:

```sh
openocd -f board/agm/agm32_vf407-cmsis-dap.cfg \
  -c init -c halt \
  -c 'flash write_image erase firmware.bin 0x80000000 bin' \
  -c 'verify_image firmware.bin 0x80000000 bin' \
  -c shutdown
```

The existing explicit entry points remain supported:

```tcl
agrv2k_flash_erase 0x80000000 0x10000
agrv2k_flash_program firmware.bin 0x80000000
```

Choose the erase length from the actual image size, rounded up to complete
4096-byte sectors. Preserve any unrelated bytes sharing the final sector.
`agrv2k_flash_program` writes and verifies; it does not erase first.
Reset the board after programming a new firmware image.

The board profile registers only the configured writable prefix of the
1 MiB main Flash at `0x80000000`. Its VF407 default is `0xe7000` bytes;
set `AGRV2K_FLASH_WRITABLE_SIZE` before loading the profile to use a smaller
application partition, such as `0xde000` for the current coreboard layout.
No option-byte programming or direct CPLD JTAG configuration is implemented.
Factory `combined.bin` containers must be decoded into addressed payloads.

## Checks

`testing/agm/test-agrv2k-dm.c` covers bounded SRAM batches, sticky SBA errors,
timeouts and rejection without replay. `testing/agm/test-flash-loader.py`
executes the shipped machine code against a bounded controller/buffer model,
including wraparound, busy polling, controller errors and host aborts.
`testing/agm/flash-contracts.tcl` checks compatibility wrapper bounds and
delegation without any target I/O. These checks run in the Windows workflow
on `feat-agrv2k-support`; the fork's default branch follows upstream.
